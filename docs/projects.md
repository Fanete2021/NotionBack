# Projects

## Сценарий 4. Создание проектов внутри воркспейса

**Что видит пользователь:** В сайдбаре, в секции «ПРОЕКТЫ», нажимает кнопку «+». Появляется новый элемент в списке — сразу в режиме редактирования, с пустым полем названия и дефолтной иконкой. Можно также выбрать цвет (из палитры) и иконку (emoji picker).

**Что делает:** Вводит название, например «Диплом». Опционально выбирает цвет (фиолетовый ●) и иконку (📄). Нажимает Enter.

**UX как в VS Code:** Пока пользователь не ввёл название и не нажал Enter, запрос НЕ отправляется — проект локально ещё не создан. Отмена (Escape / клик вне) просто убирает поле без последствий. Дефолтное название (если нужно) подставляет фронтенд. Без введённого названия создать проект нельзя.

**Что происходит внутри:** `POST /api/workspaces/:workspaceId/projects` (тело: `{ name, color?, icon?, parentProjectId? }`). Сервер:

- `assertMemberOf(workspaceId, userId)` — проверяет, что пользователь — член воркспейса.
- Валидирует `name` (`@Transform` trim + `@IsNotEmpty`) — пустое имя или строка из пробелов → 400. Проект без названия сервер не создаёт.
- position клиентом не передаётся — новый проект ставится в конец списка соседей (position = количество соседей).
- Создаёт Project с workspaceId, parentProjectId = null (корневой проект).
- Возвращает созданный проект.

**Результат:** В сайдбаре, в секции «ПРОЕКТЫ», появляется «● Диплом» с выбранной иконкой. Проект — корневой (на верхнем уровне иерархии).

**Ошибки:**

- Пользователь не член воркспейса → 403.
- Пустое название → 400.
- Воркспейс не найден → 404.

## Сценарий 5. Создание проекта внутри проекта (подпроект)

**Что видит пользователь:** В сайдбаре наводит на существующий проект «Диплом», появляется кнопка «+» или контекстное меню. Нажимает. Появляется новый вложенный элемент с отступом, сразу в режиме редактирования.

**Что делает:** Вводит название, например «Глава 1». Выбирает цвет и иконку.

**Что происходит внутри:** `POST /api/workspaces/:workspaceId/projects` (тело: `{ name, color?, icon?, parentProjectId: "uuid-диплома", position? }`). Сервер:

- Проверяет членство в воркспейсе.
- Проверяет, что parentProjectId принадлежит этому же воркспейсу.
- Создаёт проект с parentProjectId = "uuid-диплома".
- Циклов нет (осознанно — защита от циклов не реализована, как указано в нюансах).

**Результат:** В сайдбаре «Диплом» раскрывается (появляется ▸), и внутри виден «Глава 1» с отступом.

```
ПРОЕКТЫ
  ● Диплом
      📄 Глава 1
  ● Клиенты
```

**Ошибки:**

- parentProjectId указывает на проект из другого воркспейса или не существует → 400.
- Пользователь не член воркспейса → 403.
- Пустое название → 400.
- Воркспейс не найден → 404.

**Важно:** Вложенность без ограничения глубины. Можно создать проект внутри проекта внутри проекта и т.д. При удалении родительского проекта дочерние удаляются каскадно (onDelete: Cascade на parentProjectId).

## Сценарий 8. Обновление проекта (его данных)

**Что видит пользователь:** В сайдбаре нажимает на название проекта (или кнопку «...» → «Редактировать»). Появляется возможность изменить: название, цвет, иконку. Это inline-редактирование или small popover.

**Что делает:** Меняет цвет с фиолетового на зелёный. Переименовывает «Клиенты» в «Заказчики». Нажимает Enter / кликает вне.

**Что происходит внутри:** `PATCH /api/projects/:id` (тело: `{ name?, color?, icon? }` — частичное обновление). Сервер:

- `assertMemberOf` — любой член воркспейса может редактировать любой проект в нём.
- Обновляет только переданные поля (partial update).
- Возвращает обновлённый проект.

**Результат:** В сайдбаре проект теперь называется «Заказчики» с зелёным маркером ●.

**Ошибки:**

- Пользователь не член воркспейса → 403.
- Проект не найден → 404.

**Что нельзя обновить через этот эндпоинт:** workspaceId и position. `parentProjectId` — обновлять можно (перемещение, сценарий 9). Точная позиция задаётся через bulk reorder (сценарий 9).

## Сценарий 9. Перемещение проекта из одного места в другое

**Что видит пользователь:** В сайдбаре grabbing-жестом (drag-n-drop) перетаскивает проект «Планирование Q4» из корневого уровня внутрь проекта «Продукт». Либо через контекстное меню → «Переместить в...».

**Что происходит внутри:** Перемещение = смена родителя + смена позиции, два эндпоинта:

1. `PATCH /api/projects/:id` (тело: `{ parentProjectId }`). Сервер:
   - Проверяет членство.
   - Проверяет, что целевой проект существует и в том же воркспейсе (иначе 400).
   - Обновляет parentProjectId; проект попадает в конец списка нового родителя.
   - Защиты от циклов нет — если пользователь переместит A → B → A, это создаст цикл (осознанное решение).
   - `parentProjectId = null` — перемещение в корень.

2. `PATCH /api/workspaces/:workspaceId/projects/order` (тело: `{ parentProjectId?, orderedIds: [...] }`) — bulk reorder. Сервер:
   - Проверяет членство.
   - Проверяет parentProjectId (если задан) в том же воркспейсе.
   - Проверяет, что orderedIds — точная перестановка всех соседей данного родителя (иначе 400).
   - В одной транзакции переписывает position = индекс в orderedIds.
   - Возвращает обновлённое дерево проектов.

**Результат:** Проект «Планирование Q4» теперь вложен в «Продукт»:

```
Было:                          Стало:
  ▸ Продукт                      ▸ Продукт
      📄 Дизайн-система              📄 Дизайн-система
      📄 Компоненты                  📄 Компоненты
      ▸ Дорожная карта              ▸ Дорожная карта
  ▸ Планирование Q4  ←── moved ──►      ▸ Планирование Q4
  ▸ Клиенты                      ▸ Клиенты
```

Крайний случай — перемещение в корень: parentProjectId = null — проект становится корневым.

Крайний случай — удаление родителя: Если родительский проект удаляется (Cascade), все дочерние проекты тоже удаляются. Перемещать их заранее не нужно — это решение пользователя.

## Сценарий 12. Удаление проекта

**Что видит пользователь:** В сайдбаре контекстное меню на проекте «Финансы» → «Удалить». Подтверждение: «Проект и все его дочерние проекты будут удалены. Страницы внутри проекта тоже будут удалены».

**Что делает:** Подтверждает.

**Что происходит внутри:** `DELETE /api/projects/:id`. Сервер:

- `assertMemberOf` — любой член воркспейса может удалить любой проект.
- Удаляет Project. Cascade:
  - Дочерние проекты (по parentProjectId Cascade) — удаляются рекурсивно всё дерево подпроектов.
  - Страницы внутри этих проектов (по projectId Cascade) — удаляются вместе с PageContent.
  - Если были страницы без проекта (projectId = null) в этом воркспейсе — они не затрагиваются.

**Результат:** Проект «Финансы» исчезает из сайдбара. Все его подпроекты и страницы удалены безвозвратно (жёсткое удаление, не soft-delete — корзина только для страниц).

```
Было:                          Стало:
  ▸ Продукт                      ▸ Продукт
  ▸ Клиенты                      ▸ Клиенты
  ● Финансы  ←── удалён
      📄 Бюджет Q3  ←── удалён (cascade)
      📄 Отчёт Q4  ←── удалён (cascade)
```

Крайний случай — удаление проекта со страницами, у которых есть дочерние страницы: Все удаляются каскадно — вся ветка.

**Важно:** Проекты не имеют soft-delete (deletedAt). Удаление проекта — окончательное. Это отличается от страниц, где есть корзина.
