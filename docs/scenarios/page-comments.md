# Комментарии к страницам (NOT-22)

Комментарии привязаны к странице. Комментарий к фрагменту текста использует `anchorId` — тот же id, что mark/anchor в TipTap JSON на фронте. Без `anchorId` комментарий относится к странице целиком.

У каждого комментария есть статус **resolved** (закрыт / решён).

## Сценарий: комментарий к выделенному тексту

**Что делает пользователь:** выделяет текст в редакторе и добавляет комментарий.

**API:** `POST /api/pages/{pageId}/comments`

```json
{
  "body": "Нужно уточнить формулировку.",
  "anchorId": "mark-uuid-from-tiptap"
}
```

Сервер проверяет JWT, загружает страницу (не в корзине), проверяет членство в воркспейсе, сохраняет комментарий.

**Ответ:** `PageCommentEntity` с `authorInfo`, `resolved: false`.

## Сценарий: список комментариев страницы

**API:** `GET /api/pages/{pageId}/comments`

Query (опционально):

- `anchorId` — только комментарии к этому mark
- `resolved=true|false` — фильтр по статусу

Порядок: по `createdAt` ascending.

## Сценарий: resolve

**API:** `PATCH /api/pages/{pageId}/comments/{commentId}/resolved`

```json
{ "resolved": true }
```

Любой член воркспейса может закрыть или снова открыть комментарий. При `resolved: true` заполняются `resolvedAt` и `resolvedBy`.

## Сценарий: редактирование и удаление

- `PATCH /api/pages/{pageId}/comments/{commentId}` — только **автор**, меняется только `body`.
- `DELETE /api/pages/{pageId}/comments/{commentId}` — автор **или** OWNER/ADMIN воркспейса.

## Ошибки

| Ситуация | Код |
|----------|-----|
| Не член воркспейса | 403 |
| Страница или комментарий не найдены | 404 |
| Редактирование чужого комментария | 403 |
| Пустой body | 400 |
