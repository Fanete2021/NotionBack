# Регистрация

## Сценарий 1. Регистрация

**Что видит пользователь:** Форма входа — поля email, пароль, имя. Кнопка «Зарегистрироваться».

**Что делает:** Вводит email, пароль (минимум 8 символов), имя. Нажимает «Зарегистрироваться».

**Что происходит внутри:** `POST /api/auth/register`. Сервер:

- Хеширует пароль (bcrypt/argon2).
- Создаёт User.
- Отдаёт access-токен (JWT, 15 мин) + refresh-токен (httpOnly cookie, 30 дней).

**Важно:** Регистрация **не создаёт воркспейс автоматически**. После первого входа у пользователя нет ни одного воркспейса, и фронтенд должен предложить создать его (сценарий 2 в `workspaces.md`). Решение принято на ревью: пользователь сам создаёт себе воркспейс.

**Результат:** Пользователь авторизован. В куке — refresh, в памяти клиента — access. Далее — сценарий «Создание своего воркспейса» (workspaces.md).

**Ошибки:**

- Email уже занят → 409.
- Пароль < 8 символов или невалидный email → 400 (валидация DTO).
- Общие ошибки → формат `{ statusCode, message, error, path, timestamp }`.
